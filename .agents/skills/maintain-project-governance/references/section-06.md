- Record a stage as accepted only after every criterion has evidence. A passing unit test, existing-suite baseline or request-payload capture proves only its stated boundary; it does not establish the entire stage, model judgment quality, live source behavior or production readiness. When preserved real-source data is too narrow, continue a separately authorized technical implementation but keep the gate `NOT_ACCEPTED`: write a corpus inventory, immutable source hashes and a deterministic verifier, and list each missing real variant as `NOT_TESTED`. If corpus breadth is the only blocker, obtain a separate bounded-capture decision with a hard request cap and explicit exclusions for models, production databases, authentication and hidden APIs; keep the next sibling inactive until an independent corpus verdict arrives. After capture, distinguish observed variants from `NOT_CLAIMED` future variants. An absent field may cease to block a limited gate only when broad detail and search-row counts support it as an observed source invariant and an independent reviewer accepts that classification; never turn the inference into a universal schema claim. Synthetic mutations can prove fail-closed mechanics, never source-format diversity or corpus completeness. Name original databases, new test databases and capture-only databases distinctly in receipts so a zero-task claim cannot be attached to the wrong database.
